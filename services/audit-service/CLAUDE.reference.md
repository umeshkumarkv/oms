# audit-service — reference

## API

All endpoints share base path `/api/v1/audit` (`@RequestMapping` on `AuditController`). All are GET-only. The `X-User-Role` header is required on every call; allowed roles: `VIEWER`, `OPERATIONS`, `ADMIN`, `TRADER`, `SYSTEM`.

**AuditController** (`controller/AuditController.java`)

| Method | Path | Handler | Purpose |
|--------|------|---------|---------|
| GET | `/api/v1/audit/orders/{id}` | `getOrderAuditTrail(@PathVariable UUID id)` | Returns full audit trail for a single order identified by its UUID; all records sorted by `eventTimestamp DESC`. |
| GET | `/api/v1/audit/trail` | `getAuditTrail(clientId?, from?, to?, entityType?, page, size)` | Paginated audit trail; filters by `clientId` when supplied; `page` defaults to 0, `size` defaults to 20. Parameters `from`, `to`, and `entityType` are accepted but **not forwarded to the repository** — the underlying query ignores them. |

**Response envelope (both endpoints):**
```
{
  "data": {
    "records": [ AuditLogResponse ],
    "totalElements": long
  },
  "meta": {
    "timestamp": ISO-8601 string,
    "requestId": UUID string
  }
}
```

**AuditLogResponse fields:** `id`, `entityType`, `entityId`, `previousState`, `newState`, `actorId`, `actorType`, `eventTimestamp`, `metadata` (all strings; nulls preserved).

**Error envelope (auth failures and unhandled exceptions):**
```
{
  "error": { "code": string, "message": string, "details": [] },
  "meta":  { "timestamp": string, "requestId": string }
}
```
- 401 UNAUTHORIZED — missing or blank `X-User-Role` header (`RoleAuthorizationFilter`)
- 403 FORBIDDEN — role not in allowed set (`RoleAuthorizationFilter`)
- 400 BAD_REQUEST — `ValidationException` thrown by service (`GlobalExceptionHandler`)
- 500 INTERNAL_ERROR — any unhandled exception (`GlobalExceptionHandler`)

**Actuator endpoints** (no role header required): `GET /actuator/health`, `GET /actuator/info`, `GET /actuator/metrics`. Health probes enabled; details always shown.

## Data

**Table: `audit_schema.audit_logs`**

| Column | Type | Constraints | Notes |
|--------|------|-------------|-------|
| `id` | UUID | PK, NOT NULL, default `gen_random_uuid()` | Auto-generated by DB (JPA `GenerationType.UUID`) |
| `entity_type` | VARCHAR(100) | NOT NULL | `"ORDER"` or `"EXECUTION"` in current consumers |
| `entity_id` | UUID | NOT NULL | Order UUID for both entity types |
| `previous_state` | VARCHAR(100) | nullable | Prior state; null for `EXECUTION` records |
| `new_state` | VARCHAR(100) | NOT NULL | Target state or fill type |
| `actor_id` | UUID | nullable | User UUID; null for system-triggered events |
| `actor_type` | VARCHAR(20) | NOT NULL, CHECK (`USER`, `SYSTEM`) | Enum enforced at DB and JPA level |
| `event_timestamp` | TIMESTAMPTZ | NOT NULL, default `now()` | Sourced from Kafka event; falls back to `Instant.now()` if missing or unparseable |
| `client_id` | UUID | nullable | Added by V3 migration |
| `metadata` | TEXT | nullable | JSON string; enriched with rejection data for `RISK_REJECTED` events |

**Indexes:**
- `idx_audit_entity_id` on `entity_id` (V1)
- `idx_audit_entity_type` on `entity_type` (V1)
- `idx_audit_event_timestamp` on `event_timestamp` (V1)
- `idx_audit_client_id` on `client_id` (V3)

**Repository query methods** (`AuditLogRepository`):
- `findByClientIdOrderByEventTimestampDesc(UUID clientId, Pageable)` — paginated, filtered by client
- `findAllByOrderByEventTimestampDesc(Pageable)` — paginated, all records
- `findByEntityIdOrderByEventTimestampDesc(UUID entityId)` — unpaginated list, used by order trail endpoint
- `existsByEntityIdAndNewStateAndEventTimestamp(UUID, String, Instant)` — idempotency check for `order.state.changed`

**Flyway migrations** (schema: `audit_schema`, `baseline-on-migrate: true`):
- `V1__schema.sql` — creates `audit_logs` table with all original columns and three indexes
- `V2__seed.sql` — no-op comment only; no seed data (logs created by Kafka consumers)
- `V3__add_client_id.sql` — adds `client_id UUID` column and `idx_audit_client_id` index

**JPA configuration:** `ddl-auto: validate` — Hibernate validates schema against entity on startup; mismatches abort boot.

## Integrations

**Kafka — consumed topics** (`kafka/consumer/AuditEventConsumer.java`):

| Topic | Consumer group | Handler method | Required fields | Optional fields |
|-------|---------------|----------------|-----------------|-----------------|
| `order.state.changed` | `audit-service-order.state.changed-group` | `consumeOrderStateChanged` | `orderId` (UUID), `toState` | `fromState`, `clientId`, `userId`, `triggeredBy`, `timestamp`, `metadata` (for RISK_REJECTED) |
| `execution.completed` | `audit-service-execution.completed-group` | `consumeExecutionCompleted` | `orderId` (UUID), `fillType` | `clientId`, `symbol`, `side`, `executedQty`, `executedPrice`, `fillValue`, `executedAt` |

**Kafka — produced topics:** None explicitly published by business logic. A `KafkaTemplate<String, Object>` bean exists solely to back the `DeadLetterPublishingRecoverer`. Failed messages after 3 retries are published to the corresponding `.DLT` topic automatically by Spring Kafka.

**Kafka error handling:**
- Exponential backoff: initial interval 1 000 ms, multiplier 2.0, max attempts 3 (delays: 1 s → 2 s → 4 s).
- After 3 failures: `DeadLetterPublishingRecoverer` publishes to `<original-topic>.DLT`.
- Deserialization: `JsonDeserializer` with `USE_TYPE_INFO_HEADERS=false`, default type `java.util.LinkedHashMap`; trusted packages `com.brokerdealer.*`.

**Redis** (`config/RedisConfig.java`):
- Host: `${SPRING_REDIS_HOST:localhost}`, port: `${SPRING_REDIS_PORT:6379}`, timeout: 2 000 ms.
- `CacheManager` configured with 30 s TTL and JSON (Jackson) value serialization.
- No `@Cacheable` annotations present in service layer; cache infrastructure is wired but not used.

**External services:** None. The service does not make any outbound HTTP calls.

## Tech debt

**TODO / FIXME count:** 0 — no TODO or FIXME comments found in `src/`.

**Structural issues:**

1. **Dead query parameters** (`controller/AuditController.java`, `service/AuditService.java`): `GET /api/v1/audit/trail` accepts `from`, `to`, and `entityType` parameters but `AuditService.getAuditTrail` receives only `clientId`, `page`, and `size`. The three filter params are silently dropped; callers expecting them to work will get unfiltered results.

2. **Unused Redis cache** (`config/RedisConfig.java`): `RedisCacheManager` is configured with a 30 s TTL but no `@Cacheable` annotation exists in the service layer. Redis connection is required at startup even though caching does nothing.

3. **Role comment vs. code mismatch** (`filter/RoleAuthorizationFilter.java`, Javadoc comment): The class-level Javadoc says "ADMIN excluded per BRD 12.2" but `AUDIT_READ_ROLES` contains `ADMIN`. The code (not the comment) is the authoritative behavior; the comment is stale.

4. **MapStruct on classpath, not used** (`pom.xml`): MapStruct is declared as a dependency and its annotation processor is configured in the root POM, but no mapper interface exists in audit-service. DTO mapping is done manually in `AuditService.toResponse()`.

5. **Java version mismatch blocks tests**: The build requires Java 21 but the runtime available in the current environment is Java 24, causing Lombok/MapStruct annotation processor failure. Tests cannot run without switching to Java 21.

## Open questions

1. **BRD 12.2 ADMIN exclusion:** The filter Javadoc states "ADMIN excluded per BRD 12.2" but `ADMIN` is present in `AUDIT_READ_ROLES` and tests confirm ADMIN access is allowed. Was BRD 12.2 superseded, or is this a code bug? A product owner or compliance review should resolve this.

2. **`from`, `to`, `entityType` filter implementation:** The OpenAPI spec documents these as supported query parameters and consumers may rely on them. Should the repository be extended with a `findByClientIdAndEventTimestampBetweenAndEntityType` query, or should the OpenAPI spec be updated to remove these parameters? This is a product/backend decision.
