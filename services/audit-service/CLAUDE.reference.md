# Audit Service — Reference

<!-- plumbline:begin reference -->
Last updated: 4369a80 (2026-10-28, /pl-onboard, claude-reference v1)

## API

All endpoints are under `AuditController` (`/api/v1/audit`). All require `X-User-Role` header with an allowed role (see Security in CLAUDE.md). No write endpoints exist.

| Method | Path | Handler | Purpose |
|--------|------|---------|---------|
| GET | `/api/v1/audit/orders/{id}` | `AuditController.getOrderAuditTrail` | Returns all audit log entries for a given order UUID, newest first |
| GET | `/api/v1/audit/trail` | `AuditController.getAuditTrail` | Returns paginated audit trail; optional `clientId` (UUID), `from`, `to`, `entityType` params; `page` (default 0), `size` (default 20) — note: `from`, `to`, `entityType` params are accepted but not forwarded to the query |

**Actuator endpoints** (no auth): `GET /actuator/health`, `GET /actuator/info`, `GET /actuator/metrics`

## Data

### Table: `audit_schema.audit_logs`

| Column | Type | Constraints | Notes |
|--------|------|-------------|-------|
| `id` | UUID | PK, NOT NULL, default `gen_random_uuid()` | Generated by DB or JPA UUID strategy |
| `entity_type` | VARCHAR(100) | NOT NULL | `"ORDER"` or `"EXECUTION"` in current consumers |
| `entity_id` | UUID | NOT NULL | Order UUID |
| `previous_state` | VARCHAR(100) | nullable | `fromState` from event; null for execution records |
| `new_state` | VARCHAR(100) | NOT NULL | `toState` or `fillType` |
| `actor_id` | UUID | nullable | User UUID when `ActorType.USER`; null for SYSTEM actions |
| `actor_type` | VARCHAR(20) | NOT NULL, CHECK IN ('USER','SYSTEM') | Derived from `triggeredBy` prefix `"USER:"` |
| `event_timestamp` | TIMESTAMPTZ | NOT NULL, default `now()` | Parsed from event payload; falls back to `Instant.now()` |
| `client_id` | UUID | nullable | Added in V3 migration |
| `metadata` | TEXT | nullable | JSON blob; varies by event type |

**Indexes:** `idx_audit_entity_id` (entity_id), `idx_audit_entity_type` (entity_type), `idx_audit_event_timestamp` (event_timestamp), `idx_audit_client_id` (client_id)

**Flyway migrations:**
- `V1__schema.sql` — creates `audit_logs` table and first 3 indexes
- `V2__seed.sql` — seed data (contents not load-bearing for runtime)
- `V3__add_client_id.sql` — adds `client_id UUID` column and its index

**Duplicate detection key:** (`entity_id`, `new_state`, `event_timestamp`) — checked before inserting `order.state.changed` events only.

## Integrations

### Kafka — consumed topics

| Topic | Consumer method | Group ID | What is stored |
|-------|----------------|----------|----------------|
| `order.state.changed` | `AuditEventConsumer.consumeOrderStateChanged` | `audit-service-order.state.changed-group` | ORDER entity audit log; includes rejection metadata when `toState == RISK_REJECTED` |
| `execution.completed` | `AuditEventConsumer.consumeExecutionCompleted` | `audit-service-execution.completed-group` | EXECUTION entity audit log with fill details |

### Kafka — error handling (dead-letter topics)

Failed messages (after 3 exponential back-off attempts: 1 s, 2 s, 4 s) are published by `DeadLetterPublishingRecoverer` to:
- `order.state.changed.DLT`
- `execution.completed.DLT`

(Topics pre-created by docker-compose Kafka config.)

### Kafka — produced topics

None. The `KafkaTemplate` bean and `ProducerFactory` are defined (required by `DeadLetterPublishingRecoverer`) but no application code publishes events directly.

### Redis

Used as a Spring `CacheManager` (30-second TTL, null values excluded). No explicit `@Cacheable` annotations were found in the current codebase — the cache infrastructure is wired but not yet applied to service methods.

### Outbound HTTP

None.

## Configuration

All secrets and connection details are injected via environment variables.

| Environment variable | Default in `application.yml` | Purpose |
|---------------------|------------------------------|---------|
| `SPRING_DATASOURCE_URL` | (none — required) | PostgreSQL JDBC URL; docker-compose sets `jdbc:postgresql://postgres:5432/brokerdealer?currentSchema=audit_schema` |
| `SPRING_DATASOURCE_USERNAME` | `brokerdealer` | DB username |
| `SPRING_DATASOURCE_PASSWORD` | `brokerdealer` | DB password — treat as secret; must be rotated in production |
| `SPRING_KAFKA_BOOTSTRAP_SERVERS` | `localhost:9092` | Kafka broker address |
| `SPRING_REDIS_HOST` | `localhost` | Redis hostname |
| `SPRING_REDIS_PORT` | `6379` | Redis port |
| `JWT_SECRET` | (none in this service) | Declared in docker-compose for the container; not consumed by this service's code — JWT validation is the gateway's responsibility |

**Kafka consumer behaviour:**
- `auto-offset-reset: earliest`
- `spring.json.trusted.packages: com.brokerdealer.*`
- Deserializes to `java.util.LinkedHashMap` (type info headers disabled)

**Resilience4j (default instance):**
- Circuit breaker: sliding window 10, failure threshold 50%, open-state wait 10 s, half-open calls 3
- Time limiter: timeout 2 s

**Actuator exposure:** `health`, `info`, `metrics` — health probes enabled with `show-details: always`.

**Logging:** `com.brokerdealer` at INFO; `org.springframework.kafka` at WARN.
